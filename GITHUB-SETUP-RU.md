# Fox Launcher 1.4.0 — подключение GitHub

## 0. Сначала обнови свою базу
В своём Supabase открой SQL Editor → New query. Актуальные детали миграции и оплаты — в RELEASE-1.4-RU.md. Вставь весь файл `backend/migrate-1.4.sql` и нажми Run. Он рассчитан на уже установленную базу 1.2 и сохраняет аккаунты, балансы и прогресс. Полный `supabase.sql` повторно НЕ запускай. Перед миграцией сделай резервную копию. Перезапусти лаунчер.

## 1. Создай репозиторий
1. Войди на https://github.com и нажми **+ → New repository**.
2. Имя, например `fox-launcher`. Выбери **Public**: клиенты без токенов должны читать новости и релизы. Не загружай личные данные!
3. Нажми **Create repository**. В пустом репозитории создай `README.md` через **creating a new file** — так появится ветка `main`.
4. В админ-панели лаунчера (Ctrl+Shift+A → вход) заполни:
   - **GitHub — владелец**: твой логин, не email и не ссылка;
   - **Репозиторий**: `fox-launcher`, без `.git`;
   - **Ветка**: `main`.
5. Нажми **Сохранить подключения**, затем снова войди в Fox ID. Существующие поля Supabase не очищай.

## 2. Разреши публикацию новостей только себе
1. GitHub → аватар → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.
2. Задай название, срок действия и свой аккаунт в **Resource owner**.
3. **Repository access → Only select repositories** → выбери только `fox-launcher`.
4. **Repository permissions → Contents → Read and write**. Доступ ко всем репозиториям не нужен.
5. Создай токен. Вставь его ТОЛЬКО в поле **Твой fine-grained GitHub token** внутри админ-панели и нажми **Сохранить токен**. Не отправляй токен в чат, не клади в исходники, SQL, `fox-services.json` или релиз.
6. Создай новость без отметки «Черновик» и нажми **Опубликовать ленту всем**. В репозитории появится `fox-news.json`.
7. У друзей новости обновятся при запуске и в течение 5 минут. Пока у них не настроен этот репозиторий, они его не увидят.

## 3. Подключи друзей
Нажми **Конфигурация для друзей**. Полученный `fox-services.json` передай рядом с EXE. В нём только публичные настройки — GitHub-токена там нет. Перезапусти лаунчер.
Если на компьютере уже сохранены старые подключения в настройках лаунчера, они имеют приоритет: обнови их через админ-панель. Чтобы GitHub был встроен в будущую сборку, включи сохранённые owner/repo в исходный `fox-services.json` и пересобери.
В текущем EXE уже есть подключение Supabase. GitHub пока не встроен: твой логин и имя репозитория ещё не указаны.

## 4. Выложи portable 1.4.0 вручную
Репозиторий → **Releases → Draft a new release** → новый тег `v1.4.0`, target `main`, заголовок `Fox Launcher 1.4.0`. Прикрепи `FoxLauncher-Portable-1.4.0.exe` и публичный `fox-services.json`, затем **Publish release**.
Portable обновляется вручную: закрой лаунчер и замени EXE. Сборки и аккаунты сохраняются в папке данных. Токен для чтения публичного релиза друзьям не нужен.

## 5. Сборки через GitHub Actions (необязательно)
Загрузи содержимое папки исходников в корень репозитория, включая скрытую `.github/workflows/windows.yml`, `package-lock.json`, assets и публичный `fox-services.json`. НЕ загружай `node_modules`, `dist`, папку данных, пароли и токены. Загрузка через GitHub может пропускать скрытые папки — проверь workflow отдельно.
Открой **Actions → Build Windows → Run workflow**. После успешной сборки скачай `FoxLauncher-Windows` из Artifacts. Он содержит portable, установщик, `latest.yml` и blockmap.
При push нового тега `v*` workflow также создаст GitHub Release с файлами обновления. Для этого тег должен запускать workflow уже с загруженными исходниками. Если тег `v1.4.0` и релиз уже созданы вручную, не создавай их повторно: для следующего выпуска используй новый номер.
Автоустановка обновлений работает только у установленной NSIS-версии с настроенным публичным GitHub. В release должны быть установщик, `latest.yml` и `.blockmap` именно от одной сборки. Не переименовывай эти файлы. Portable не устанавливает обновления автоматически.

## Скидки и подписки
В админ-панели появился блок **Скидки магазина**. Выбери товар или «Скидка на улучшение подписки», введи процент и сохрани. 0 отключает скидку. Улучшение по умолчанию — 5% (диапазон 0–50%), товары — 0–90%.
Скидки применяются последовательно: Pro за 700 с товарной скидкой 10% и скидкой апгрейда 5% стоит `ceil(700 × 0.9 × 0.95) = 599` Фоксов.
Улучшение оплачивает новый тариф со скидкой, а НЕ только разницу цен. Старая подписка заменяется новой; остаток срока сохраняется и добавляются 30 дней. Продление добавляет 30 дней без скидки апгрейда. До окончания нельзя купить более низкий тариф. Все суммы проверяет сервер; изменение цены требует повторного подтверждения.


## Друзья: личный чат и звонки (Fox Launcher 3.x)

Кнопки чата и звонка используют защищённые RPC Supabase. Для базы, которая ещё не содержит эти функции, последовательно проверь и примени миграции: `backend/migrate-2.0.sql` (личный чат), затем `backend/migrate-2.1.sql`, затем `backend/migrate-2.2.sql` (сигнализация WebRTC). Перед изменениями сделай резервную копию. Не запускай миграции повторно вслепую поверх неизвестной схемы: сначала проверь, какая версия уже применена.

Чат доступен только подтверждённым друзьям. Видеозвонок требует разрешения на микрофон/камеру; если соединение не устанавливается из-за NAT или ограничений сети, может понадобиться TURN-сервер. Миграции добавляют серверную сигнализацию, но не гарантируют, что каждая сеть пропустит P2P-медиа.

Если кнопки показывают ошибку о недостающей RPC-функции, проверь, что миграция для соответствующей функции применена именно в том Supabase-проекте, который указан в публичном `fox-services.json`.
