# Fox Launcher 3.1.0 — PC Edition

Независимый Minecraft Java Launcher для Windows 10/11 x64. Проект использует Electron и Supabase. Не является продуктом Mojang или Microsoft.

## Статус проекта

- Версия 3.1.0 ориентирована на Windows-ПК. Android-клиент и сборка APK временно исключены; мобильную версию планируем отдельно для 4.0/5.0. См. `ANDROID-STATUS-RU.md`.

- Исходники лаунчера и конфигурация сборки находятся в этом репозитории.
- Проверка обновлений использует GitHub Releases: обычный push в `main` сам по себе не публикует релиз.
- Реальные платежи по умолчанию отключены.
- Изменения базы данных нужно применять последовательными миграциями к существующей базе; не запускайте полный `supabase.sql` поверх рабочей базы.

## Документы

- `BUILD-AND-HANDOFF-RU.md` — сборка проекта и выпуск обновлений.
- `RELEASE-1.5-RU.md` — прежняя инструкция по установке и SQL; часть сведений может относиться к более ранним версиям.
- `migrate-*.sql` — миграции базы. Перед применением сделайте резервную копию и проверьте порядок миграций.

## Для разработчиков

1. Установите совместимую версию Node.js.
2. Выполните `npm ci`.
3. Запустите тесты командой `npm test`.
4. Для локального запуска используйте скрипты из `package.json`.
5. Для публикации обновления создайте версионный тег `vX.Y.Z` и убедитесь, что GitHub Actions успешно собрал и опубликовал релиз.

Не публикуйте секретный ключ Supabase `service_role` в клиентском приложении или репозитории. Используйте только публичный anon/publishable key на стороне лаунчера.


## Глобальные режимы лаунчера (2.6)

Для режима тревоги, торжественного режима, технических работ и дополнительных объявлений сначала примените `backend/migrate-2.6-launcher-modes.sql` в Supabase SQL Editor. Затем соберите и выпустите обновление лаунчера. Состояние и время окончания хранятся на сервере; клиент опрашивает состояние каждые 10 секунд. Управление защищено таблицей `fox_admins`. Без миграции режимы не активируются, а обычный офлайн-запуск остаётся доступен. Автозапуск Windows настраивается в разделе «Настройки» и по умолчанию включён для нового профиля.


## Планирование глобальных режимов (2.7)

После `backend/migrate-2.6-launcher-modes.sql` примените `backend/migrate-2.7-launcher-schedule.sql` в Supabase SQL Editor. В панели владельца можно задать точные локальные даты начала и окончания или включить режим сразу. Планировщик хранит время в UTC и показывает пользователю его локальное время. Для режима тревоги окно не закрывается кнопкой; звук повторяется, а клиент автоматически закрывается через 60 секунд. При повторном входе до конца тревоги предупреждение появляется снова.

## Звуки

Клиент уже ожидает файлы в `renderer/../assets/sounds/` (то есть `assets/sounds/`) с именами из архива `звуки.zip`. Для безопасной публикации звуков из интерфейса нельзя встраивать личный GitHub token в приложение: любой пользователь сможет извлечь его. Загрузка в Git должна идти через защищённый сервер/ GitHub App с секретом на сервере; публичный CDN — отдельный URL/бакет. В предоставленном архиве нет названия CDN, URL бакета или ключа, поэтому автоматическую загрузку в неизвестный CDN не настраиваем вслепую.


## Миграции 2.7–2.8

После миграции `backend/migrate-2.6-launcher-modes.sql` примените `backend/migrate-2.7-launcher-schedule.sql` для планирования режимов. `backend/migrate-2.8-owner-ruble-balance.sql` добавляет защищённые RPC владельца для установки точного внутреннего рублёвого баланса и выдачи учётных рублей. Вводимая сумма указывается в рублях, в базе хранится в копейках. Это внутренняя игровая валюта, не подтверждение реального платежа. Миграции не меняют таблицу владельцев: пользователь должен уже находиться в `fox_admins`.
